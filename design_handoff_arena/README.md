# Handoff: Arena — платформа боёв (лендинг + приложение)

## Overview
Arena — веб-платформа, где пользователь собирает отряд из шести бойцов, качает их статы, редактирует и выводит на бой. Исход боя считается сравнением одного выбранного параметра по шести парам: кто выиграл больше раундов, тот забрал бой.

Дизайн состоит из двух независимых частей:
1. **Лендинг** (`Landing.dc.html`) — вовлекающая игровая страница: интерактивный драфт отряда прямо в герое, живая лента боёв, играбельная демо-дуэль, интерактивный блок стихий, интерактивная раздача очков прокачки.
2. **Приложение** (`Arena.dc.html`) — рабочие экраны: выбор бойца, покедекс, досье бойца, прокачка, сборка составов 6v6, арена (битва), результат, история боёв.

Источник данных в репозитории уже есть: `public/data/pokemon.json` (снимок PokéAPI через `scripts/fetch-pokemon.ts`), `src/shared/api/static-dataset.ts`, `src/shared/lib/db.ts` (Dexie), `src/entities/fighter/model/merge.ts`. Дизайн построен ровно на этой модели: база — неизменяемый снимок, правки пользователя — отдельный слой, кастомные статы — сверху.

**Важно про контент:** в макетах используются оригинальные бойцы Arena (Фламбер, Тидрак, Вердал…), а не покемоны — арт и имена покемонов защищены авторским правом. Структура данных при этом идентична PokéAPI (id, типы, шесть base stats, эволюции), поэтому подстановка реальных данных из `pokemon.json` не требует изменений в вёрстке: все места под арт — плейсхолдеры-слоты фиксированных размеров.

## About the Design Files
Файлы `Landing.dc.html` и `Arena.dc.html` в этом бандле — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие внешний вид и поведение, а не продакшн-код для копирования. Задача — **воспроизвести эти макеты в существующем окружении проекта**: Next.js (App Router) + Tailwind CSS + shadcn/ui, по сложившимся в репозитории паттернам (FSD-структура `src/entities`, `src/shared`, `src/components/ui`).

Все стили в референсах — инлайновые: это особенность среды прототипирования, а не рекомендация. В проекте цвета объявить CSS-переменными в `src/app/globals.css` и использовать через Tailwind-токены, а не хардкодить hex по компонентам.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, отступы, радиусы и интерактив. Воспроизводить пиксельно, но средствами Tailwind и shadcn/ui, а не копированием инлайновых стилей.

Единственное, что заведомо не финально, — арт бойцов: везде полосатые слоты-плейсхолдеры с моно-подписью. На их место встают спрайты из поля `sprite` (official-artwork) в `pokemon.json`.

## Design Tokens

### Цвет (шесть значений, больше не добавлять)
| Токен | Hex | Назначение |
|---|---|---|
| `--white` | `#FFFFFF` | основной текст на тёмном, primary-кнопки |

| `--blue` | `#ADDAEE` | Команда B, «водные»/защитные стихии |
| `--mint` | `#B2FFE2` | успех, прокачка, свободные очки, аватар |
| `--amber` | `#FFB444` | Команда A, primary-акцент, победа, CTA |

Производные (использовать именно эти значения):
- текст приглушённый: `rgba(255,255,255,.6)` — описания; `rgba(255,255,255,.45)` — подписи; `rgba(255,255,255,.42)` — моно-кикеры; `rgba(255,255,255,.32)` — подсказки.
- разделители/бордеры: `rgba(255,255,255,.08)`; пустой слот: `1px dashed rgba(255,255,255,.16)`.
- дорожка полосы: `rgba(255,255,255,.07)`; на пастельном фоне: `rgba(0,0,0,.13)`.
- чипы: `rgba(255,255,255,.08)` на тёмном, `rgba(0,0,0,.12)` на пастельном.
- текст на пастельном: `#000`, описания `rgba(0,0,0,.66)`, подписи `rgba(0,0,0,.55)`.
- «полупогашенная» полоса проигравшей стороны: `rgba(255,180,68,.3)` / `rgba(173,218,238,.3)`.

Правило: `amber` и `blue` появляются только там, где есть принадлежность к команде или сравнение. Стихии раскрашиваются теми же тремя пастельными (amber/blue/mint) — четвёртого цвета не вводить.

### Типографика (3 роли)
- **Outfit** (300/400/500/600/700) — заголовки, имена бойцов, названия команд, счёт. Заголовки: `font-weight:600`, `letter-spacing:-.03em` (герой `-.035em`, счёт `-.04em`), `line-height:1`.
- **Manrope** (400/500/600) — body, описания, кнопки, ссылки. 15–15.5px, `line-height:1.6`, `text-wrap:pretty`.
- **IBM Plex Mono** (400/500/600) — **все числа**: статы, id (`#041`), суммы, счёт, а также кикеры-капсы с `letter-spacing:.14em`. Моноширинность выравнивает цифры в колонки.

Шкала: 230px (декоративное контурное имя в герое) · 92–104px (счёт) · 54–66px (H1/H2) · 44–46px (имя бойца в карточке героя) · 40–48px (H2 секций) · 24–30px (подзаголовки, имена в списках) · 19–21px (заголовки карточек) · 15–15.5px (body) · 13–14px (UI-текст) · 10.5–12.5px (моно-подписи).

Курсивные надстроки («Выбери своего», «Кто такие») — Outfit 300 italic, 24–28px, `rgba(255,255,255,.55–.6)`.

### Радиусы
40px (крупные секционные блоки) · 34–38px (герой-карточка, панели) · 30–32px (карточки экранов) · 24–28px (карточки списков) · 20–22px (строки, вложенные блоки) · 16–18px (инпуты, мелкие слоты) · 12–14px (аватар, иконка-чип) · 999px (все пилюли, кнопки, полосы) · 50% (круглые кнопки-стрелки, ±).

### Отступы и сетка
- Максимальная ширина контента: **1560px**, горизонтальные паддинги 40–48px, `margin:0 auto`.
- Минимальная ширина корня: **1280px** (дизайн только под десктоп; адаптива в этой итерации нет).
- Вертикальные отступы: 88px между секциями лендинга, 72px между экранами приложения.
- Gap-шкала: 40–44px (колонки секций) · 28px · 20px · 16px (сетки карточек) · 14px · 12px · 10px · 8px (чипы) · 6–7px.
- Тени только на «поднятых» объектах: `0 50px 110px rgba(0,0,0,.66)` (герой-карточка), `0 40px 90px rgba(0,0,0,.6)`.

## Interactions & Behavior

### Лендинг — герой
- `←` / `→` и кнопки-стрелки: `index = (index ± 1 + n) % n`. Клик по карточке-соседу — прямой переход к нему.
- При смене бойца одновременно меняются: цвет карточки, glow фона, цвет лого, контурное имя, роль, ширины и цвета полос статов. Всё через CSS-transition, без re-mount.
- `Enter` или кнопка — добавить в отряд. Три состояния кнопки: «Добавить в отряд» (белая) → «Уже в отряде — убрать» (`rgba(255,255,255,.1)`, белый текст) → «Отряд собран — в арену» (mint), когда слотов 6. Повторное добавление одного бойца запрещено, больше шести — тоже.
- Клик по занятому слоту дока удаляет бойца. Появление слота — `pop 320ms`.
- CTA дока: 0 выбрано — `rgba(255,255,255,.1)`, «Открыть арену»; 1–5 — белая, «Продолжить в арене»; 6 — mint, «Отряд готов — в арену».

### Лендинг — дуэль
- Клик по чипу параметра: `ran = false` → через 60ms `ran = true`. Полосы уезжают в 0 и заезжают заново с новыми значениями (перезапуск transition).
- «Запустить бой» / «Сбросить бой» — тумблер `ran`. При `ran = false`: все ширины `0%`, значения серые (`rgba(255,255,255,.42)`), счётчики раундов 0, вердикт — нейтральная подсказка.
- Вердикт и счёт всегда считаются из тех же дуэлей, что отрисованы. **Никогда не хардкодить счёт.**

### Лендинг — стихии и прокачка
- Клик по стихии меняет карточку стихии и список бойцов; клик по бойцу в списке выбирает его в герое (`index`).
- ± меняет очки по стату: инкремент запрещён при израсходованных 7 очках, декремент — на нуле. Итог = `база + очки × 6`. «Сбросить правки» очищает все очки.

### Приложение
- Навигация — анкоры к секциям экранов; кнопка «←» в хедере ведёт на лендинг.
- Полосы статов и дуэлей запускаются анимацией `race` при монтировании (в React — при появлении секции).
- Сегментные полосы в шапке арены отражают текущий счёт раундов.
- Результат боя (счёт, победитель, золотая обводка, приглушение проигравшего, первая строка истории) **вычисляется из дуэлей**, а не задаётся константами.

### Ключевые анимации
| Имя | Свойства | Где |
|---|---|---|
| `race` | `width: 0 → target`, 620–680ms, `cubic-bezier(.15,.85,.2,1)`, stagger 70–90ms | полосы статов и дуэлей |
| `impact` | `scale(1.3 → .98 → 1)` + opacity, 520ms, `cubic-bezier(.2,.8,.2,1)` | счёт на результате |
| `goldring` | пульсация `box-shadow` amber, 2.4s, infinite | карта победителя |
| `pop` | `scale(.86 → 1.04 → 1)` + opacity, 320ms | заполнение слота отряда |
| `rise` | `translateY(16px) → 0` + opacity, 380ms, stagger 35ms | карточки покедекса |
| `ticker` | `translateX(0 → -50%)`, 34s, linear, infinite | лента боёв |
| `nudge` | `translateX(0 → 5px → 0)`, 1.6s, infinite | стрелка в CTA |
| hover-карточка | `translateY(-6…-8px)`, 220–260ms | карточки бойцов |

`@media (prefers-reduced-motion: reduce)` полностью отключает анимации и переходы (`animation:none; transition:none`) — обязательно перенести.

### Доступность
- Видимый focus-ring на всех интерактивных элементах: `outline:2px solid #ADDAEE; outline-offset:3px`.
- Кнопки-стрелки героя — с `aria-label` («Предыдущий боец» / «Следующий боец»).
- Текст на пастельных поверхностях — только `#000` и его прозрачности; на тёмных — белый и его прозрачности. Не смешивать (чёрный текст на `#232323` даёт контраст ~1.3:1).
- Слоты отряда, чипы и ± — настоящие `<button>`, а не div с onClick.
- Голос интерфейса: активный залог, короткие команды — «Собрать команду», «Начать бой», «Сбросить правки». Пустые состояния подсказывают действие: «Под эти фильтры бойцов нет — ослабь диапазон».

## State Management

### Лендинг
| Состояние | Тип | Назначение |
|---|---|---|
| `index` | number | текущий боец в герое |
| `roster` | string[] | id выбранных бойцов, максимум 6, без дублей |
| `stat` | 'hp' \| 'atk' \| 'def' \| 'spa' \| 'spd' \| 'spe' | параметр демо-дуэли |
| `ran` | boolean | дуэль запущена (управляет ширинами полос) |
| `element` | string | активная стихия |
| `points` | Record<statKey, number> | распределённые очки, сумма ≤ 7 |

Клавиатурный слушатель `keydown` на `window` (`ArrowLeft`/`ArrowRight`/`Enter`) — навешивать на маунте, снимать на анмаунте.

### Приложение
Экраны в макете статичные. При реализации подключить к существующим слоям репозитория:
- ростер и статы — `getAllFighters()` / `getFighterById()` из `src/entities/fighter/api/fighterRepository.ts`;
- правки — `db.overrides` (`fighterId`, `name`, `description`, `stats`), кастомные статы — `db.customStats` + `db.customStatValues`, склейка — `mergeFighter(base, override, customStats)`;
- составы — `db.teams` (`id`, `name`, `fighterIds`);
- историю боёв нужно добавить: новая таблица (например `battles`: `id`, `date`, `teamA`, `teamB`, `stat`, `winsA`, `winsB`) — в `db.ts` её сейчас нет;
- флаг `isEdited` из `mergeFighter` уже управляет бейджем «ИЗМЕНЁН» в покедексе.

Логика боя: для каждой из шести пар сравнить выбранный параметр (`>=` — победа A), `winsA`/`winsB` дают счёт, равенство — ничья. Победитель определяется по раундам, а не по сумме параметра (сумма может быть больше у проигравшего — это нормально и показано на экране).

Реальные изображения брать из `pokemon.json` (поле `sprite`, official-artwork). Иконок в дизайне нет: стрелки, ±, «V/S» — текстовые глифы; при желании заменить на иконки из библиотеки проекта, сохранив размеры.

Шрифты: Google Fonts — Outfit (300–700), Manrope (400–600), IBM Plex Mono (400–600). В Next.js подключать через `next/font/google`, не через `<link>`.
