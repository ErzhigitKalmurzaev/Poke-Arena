# Arena — дизайн-система

Отдай этот файл целиком Claude как бриф на визуальную реализацию платформы (лендинг, каталог, карточка бойца, тимбилдер, экран битвы). Ниже — обоснованная концепция, не шаблон.

## Концепция

Arena — конструктор команд бойцов и сравнений. Эстетика — не типичный SaaS-лендинг, а язык **боевой карточки/скаутингового досье и турнирной трансляции**: постеры взвешивания в единоборствах, статистические оверлеи прямых эфиров, карточный дро-скрин в киберспорте. Это не декоративная тема, а рабочий язык интерфейса: цифры и сравнение — главный контент продукта.

Два акцентных цвета в системе — не декоративный выбор, а прямое отражение содержания: в игре всегда две команды, у каждой свой цвет, который держится сквозной нитью через весь интерфейс (полоски статов, обводки карточек, подсветка победителя).

Проверено на типичные клише AI-дизайна и осознанно отклонено:
- тёплый крем + засечки + терракота — нет: тёмная база, гротеск, ember теплее и агрессивнее терракоты, всегда в паре со вторым акцентом;
- почти чёрный фон + один неоновый акцент — нет: два равноправных акцента с игровым обоснованием, а не одна декоративная подсветка;
- broadsheet с hairline-линиями и колонками — нет: диагональный split-layout, карточный ряд, ничего похожего на газетную вёрстку.

## Токены

### Цвет (6 значений, больше не добавлять без причины)

| Токен | Hex | Назначение |
|---|---|---|
| `ink` | `#14161C` | базовый фон, глубокий графитово-синий |
| `panel` | `#1E212B` | поверхности карточек, форм, модалок |
| `ember` | `#FF5A36` | Команда A / основной акцент, CTA |
| `cyan` | `#2EE6D6` | Команда B / вторичный акцент, hover, ссылки |
| `paper` | `#F2F1ED` | текст на тёмном фоне |
| `gold` | `#FFC94A` | победа/KO, редкие кастомные параметры |

Правило использования: `ember` и `cyan` появляются только там, где идёт явное сравнение или принадлежность к команде. Везде остальное — оттенки `ink`/`panel`/`paper`.

### Типографика (3 роли)

- **Display** — Bebas Neue (альтернатива Anton) — сжатый ударный гротеск. Только заголовки экранов, VS-блок, крупный счёт. Используется скупо.
- **Body** — Inter — нейтральный читаемый шрифт для описаний, форм, длинных текстов.
- **Data/Mono** — IBM Plex Mono — все числа: статы, id бойцов, таймеры, диапазоны фильтров. Функциональный выбор: моноширинность выравнивает цифры в колонки, как в реальных скаутинговых карточках и трансляциях.

### Layout по экранам

**Лендинг** — полноэкранный диагональный сплит вместо центрированного героя:

```
┌──────────────────────┬──────────────────────┐
│   ember glow          │          cyan glow    │
│   TEAM SILHOUETTE A   │    TEAM SILHOUETTE B  │
│                    ╲  │  ╱                    │
│                     ╲ │ ╱                     │
│                      [VS]                     │
│                     ╱ │ ╲                     │
│   "СОБЕРИ КОМАНДУ."   │    "БРОСЬ ВЫЗОВ."     │
└──────────────────────┴──────────────────────┘
```
`VS` — signature-элемент, не статичный текст (см. ниже). Под героем — горизонтальный скролл-ряд карточек бойцов (не grid) с 3D-tilt на hover.

**Каталог** — grid карточек: моно-цифры статов справа, цветной лейбл типа слева, граница появляется только на hover (намёк на "добавить в команду").

**Экран битвы** — вертикальный versus-лейаут: слева состав A (`ember`-обводка), справа состав B (`cyan`-обводка), по центру — колонка выбранного параметра с горизонтальными race-барами, "заезжающими" от края к центру при запуске.

**Шаги воронки** (состав → параметр → битва) — легитимная последовательная нумерация, потому что это реальная последовательность действий пользователя: `РАУНД 01 — СОСТАВ`, `РАУНД 02 — ПАРАМЕТР`, `РАУНД 03 — БИТВА`.

## Signature-элемент

Анимированный `VS`-блок и race-fill стат-бары при сравнении команд — единственный по-настоящему "громкий" момент дизайна, напрямую завязанный на функцию продукта (сравнение параметров), а не декоративный эффект.

## Моушн

- **Загрузка лендинга** — одна оркестрованная последовательность: диагональ героя раскрывается slash-reveal (~400ms), `VS` появляется с лёгким impact-flash. Один раз, не при каждом скролле.
- **Скролл ряда бойцов** — stagger-появление карточек (40–60ms между карточками), без bounce, без параллакса ради параллакса.
- **Hover карточки бойца** — лёгкий 3D-tilt по курсору (translate + rotate 3–5°), тень смещается по направлению наклона. Единственный интерактивный микро-момент на карточке.
- **Стат-бары сравнения** — race-fill от нуля к значению (ease-out, 500–700ms), числа считаются вверх синхронно (Data/Mono).
- **Результат битвы** — победившая сторона получает короткую вспышку `gold` по контуру, счёт "бьётся" импактом; проигравшая сторона тускнеет. Единственное место с более выраженной анимацией — оправдано смысловым весом результата.
- Везде: `prefers-reduced-motion: reduce` отключает slash-reveal, tilt и race-fill, оставляя мгновенный fade. Больше нигде анимации не добавлять — на формах, фильтрах и списках лишний моушн создаёт ощущение шаблонности, а не продуманности.

## Голос интерфейса

Активный залог, короткие команды: «Собрать команду», «Начать битву», «Сбросить правки» — не «Отправить», не «Подтвердить». Пустой каталог по фильтрам: «Под эти фильтры бойцов нет — ослабь диапазон», не «Ничего не найдено». Ошибки не извиняются, называют, что произошло и что делать: «Не получилось загрузить данные. Проверь соединение и обнови страницу».

## Планка доступности

AA-контраст `paper` на `ink`/`panel` как минимум. Видимый focus-ring на всех интерактивных элементах (обводка `cyan` 2px, не одна заливка). Полная адаптация вниз до мобильного: versus-сплит на лендинге на мобильном становится вертикальным стеком, а не сжатой копией десктопа.

## Инструкция для реализации

Технологии — Next.js + Tailwind CSS, все цвета выше объявить как CSS-переменные в `globals.css` (`--ink`, `--panel`, `--ember`, `--cyan`, `--paper`, `--gold`), не хардкодить hex по компонентам. Строить по разделам сверху вниз: сначала токены и типографика, затем лендинг с hero и signature-элементом, затем каталог, затем экран битвы. После каждого экрана — самопроверка на клише из раздела "Концепция" выше и на планку доступности.
